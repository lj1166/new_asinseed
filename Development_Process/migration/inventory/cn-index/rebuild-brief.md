| 内容项 | 类型（事实 / 新创作 / 运营维护） | 证据或素材来源 | Sanity / 代码归属 | 页面消费位置 | 留空 fallback |

## 5. 设计方向

| 项目 | 方案 |
|---|---|
| 现代 SaaS 呈现原则 | 清晰价值主张、单一视觉焦点、宽松留白、有限模块与可信证据。采用既有 token/组件，但视觉、版式、文案和媒体不以旧 JSP 为基线。 |
| 响应式重点 | 移动端首屏先呈现定位、简短说明与 CTA；场景卡片纵向排列；图片不裁切关键 UI；导航为可键盘操作的折叠菜单。 |
| 图片策略与展示比例 | Hero 可使用抽象原创产品图或已批准的产品截图；产品证据图优先 16:10 或 4:3；分享图严格 1200×630。禁止使用无法确认版权/时效的旧图。 |
| 动效 / 交互 | 只给 CTA、折叠菜单、FAQ 与状态反馈使用轻量过渡；实现 `prefers-reduced-motion`。不使用轮播、自动播放或装饰性动画。 |
| 可信度设计 | 用可验证的事实、方法边界、真实案例/评价和透明的“暂未开放”状态建立信任，而不是堆叠旧 Logo、泛化数据或夸张承诺。 |

## 6. SEO / GEO 与转化关系

| 项目 | 方案 |
|---|---|
| index / canonical / hreflang | `/cn` 可收录且 canonical 自指；简中单语言阶段不输出 hreflang/x-default。其他语言仅在独立本地化和 P4 通过后从共享注册表启用。 |
| 可直接引用的答案或证据段落 | 只在 `TBD-FACT-01` 解决后，以“适用对象、输入、能获得的洞察、限制条件”形成可引用问答或短段；不得用未经证实的规模、准确率或客户背书。 |
| 结构化数据（仅真实内容） | 保留已验证的 Organization；当站点名称、URL、官方身份完整时补充；FAQPage 仅在真实 FAQ 已发布时输出。当前不虚构 SoftwareApplication、Review 或 AggregateRating。 |
| 内链：本页如何承接/导出意图 | 首页承接品牌/核心工具词，向已发布的产品功能页、资源中心和真实 FAQ 导出；不存在的搜索、插件、博客、帮助页不创建链接。 |
| 与博客、资源、案例页的分工 | 首页负责实体、可信度和转化；资源/文章负责长尾问题、方法论、案例与 AI 可引用内容。首页只展示少量已发布内容入口，不承担批量文章收录。 |
