## 三、试点页面开发暴露的文件系统缺陷

### 3.1 缺 GEO（Generative Engine Optimization）维度

现有流程里"打分"这件事本身只面向经典搜索引擎：`seo-scoring-standard.md` 的 9 个类目（可索引性/Canonical-Hreflang/Metadata/OG/JSON-LD/标题层级/Alt/内链/性能代理）全部是"Google 能否正确收录并排名"这一件事的分解，没有一项在问"ChatGPT/Perplexity/Google AI Overview 这类生成式引擎会不会引用/推荐这个页面"。索引流程本身（`.claude/skills/jsp-page-inventory/SKILL.md` 的"归类规则"）也只回答内容该不该进 Sanity、该不该硬编码，不回答"这段内容是否具备可被 AI 引擎摘录引用的结构"。

本轮实测的 `jsonLdCount:0`（两个 locale 都是）是这个缺口最直接的实例：Organization/Article 级结构化数据、明确的作者/方法论/来源标注，是 GEO 的核心信号之一，而不仅是"加分项"。D-004 里 `ContentEntry`/`MaterialAsset` schema 已经预留了 `author`/`sourceCitations`/`methodology` 字段（E-E-A-T），但按 D-004 原文，这些字段目前对 agent 生成内容"保持可选，不强制"——这个决策是在轨B 尚未真正产出内容、且 GEO 尚未被提出为目标之前做的，现在业务目标明确纳入"AI 推荐权重"后，这条"可选"的决策依据本身值得重新评估（不是说决策错了，是说它的前提变了）。

### 3.2 没有统一的 SEO+GEO 打分标准

`seo-scoring-standard.md` 文件头就明确写了"技术审计"定位，范围是经典 SEO；GEO 相关的信号（结构化数据完整度、直接可引用的"答案块"格式、内容新鲜度/更新时间标注、实体权威性 sameAs 关联）目前**没有任何文档定义、没有打分权重、也没有出现在 P4 十项验收器里**。这直接导致本轮审计虽然发现了 `jsonLdCount:0` 这类问题，但只能把它归进现有 E 类目（JSON-LD，权重10/100）打分，而 JSON-LD 完整度对 GEO 的重要性可能不该只值 10 分——目前完全没有依据去回答"应该值多少分"，因为没有一份文档把 GEO 当作与经典 SEO 并列的第二个打分维度来设计权重分配。

### 3.3 缺少页面结构架构方案，而是直接照搬旧站结构

证据来自 `Development_Process/migration/url-map.md`"P2 内容归属决策"一节的三条已落地结论：
- testimonials 数量该不该对齐（3 vs 4）——结论是"各自独立维护，不强制对齐"，即照搬旧站两个 locale 各自的历史数量，而不是从"新站首页应该展示几条社会认同证据、放在什么位置"这个信息架构问题出发重新设计。
- footer "HOT ASIN" 链接该不该两侧同步——结论是"两侧同步去掉"，判断依据是目标页面本身不迁移，而不是"这个链接位置本身在新首页的架构里是否还有意义"。
- hot-ASIN 注释块该不该恢复——结论是"旧站已注释，不恢复"，同样是以旧站当前状态为准绳，而非独立评估。

这三条决策本身在各自的语境下都合理，但共同反映一个结构性事实：**P1→P2 之间没有一个步骤在问"这个页面的信息架构/段落顺序/内容层级，应该长成什么样才最符合 2026 年的 SEO+GEO+现代网站最佳实践"**。当前 `jsp-page-inventory` skill 的产出（`inventory.md` 的 "Index Candidate" 表）只回答"这段内容的数据该从哪来"，不回答"这段内容该不该存在、该放在页面的什么位置"。实际执行路径是"旧站有什么、新站就搬什么，顶多做取舍",不是"新站应该是什么样，再倒推旧站哪些内容能复用"。

### 3.4 缺少页面元数据和图片素材的设计维度、方案与约束

这是本轮两份打分报告里扣分最集中的类目，也是证据最直接的一类缺陷：

- **标题**：`/en` 的 `"...Research Tool-AsinSeed"` 品牌名重复拼接——没有任何文档规定标题模板的拼接规则或去重校验，全靠 DTO 文案作者自己不犯错。
- **描述**：`/en` 48字符（约30%达标）、`/zh-cn` 仅11字符（约7%达标）——没有任何硬性下限校验点，P4 十项验收器目前不检查 description 长度是否落在 SERP 摘要有效区间。
- **Open Graph 图片**：两个 locale 都完全没有 `og:image`——没有任何图片素材规范文档，不知道该用什么尺寸（社交平台标准是 1200×630）、该由谁提供（真实截图/设计稿/AI生成）、该在什么阶段产出。
- **结构化数据**：两个 locale `jsonLdCount:0`——没有"按页面类型规定必须输出哪些 JSON-LD 类型"的清单。

这些问题之所以能在 P4"试点通过"之后仍然全部存在，根因是**P4 十项验收器本身没有把这四项设成硬性检查点**——它验收的是"数据来自 DTO 而非硬编码"（取证方式层面），不验收"DTO 里的值本身是否达标"（内容质量层面）。这是两件事，本轮审计第一次把二者的差距量化出来。

### 3.5 缺少 Sanity 后台（轨B/CMS）的开发任务

轨B 当前状态（`DECISIONS.md` D-005）：schema 已建好（`contentEntry`/`keywordEntry`/`materialAsset`/`homepageFaqEntry`/`homepageTestimonialEntry`），但 `workflowState` actions、Content Release 接线、以及 SDD §12 定义的权限 Gate（限制 agent 写入身份不能把内容推进到 `approved`、不能创建/修改 Content Release）**全部暂停**，解除暂停的条件写死为"轨A 的 Stage 1 试点（`index.jsp` + `search.jsp`）通过验收"。

`index.jsp` 已经按 P4 十项验收器"通过"（`report-pilot-index.md`），但本轮审计证明这个验收器本身存在盲区（3.4节列出的四项）。这带来一个此前从未被提出过的问题：**轨B 解除暂停的阈值，到底应不应该只看 P4 十项验收器，还是应该同时要求 SEO/GEO 审计达到某个分数线？** 目前没有任何文档回答这个问题，`STATE.md` 的下一步排序里轨B 只出现"暂停中"这一个状态，没有任何"暂停期间应提前准备什么"或"解除暂停后第一批要做的具体开发项"的条目——即便 D-004/SDD §12 已经在概念上把 Gate、Studio 自定义视图这些开发项描述清楚，它们从未被转化成 STATE.md 里可排期的具体任务。

### 3.6 其他相关但用户未点名的缺口（"等等"覆盖范围）

- **现代网站风格设计没有验收锚点**：master prompt §4 只规定了技术基线（shadcn/ui + design tokens），没有任何文档定义"现代"对这个品牌具体意味着什么，P1-P4 流程里也没有视觉/风格 QA 这一步。
- **AI 爬虫访问策略未与经典 Googlebot 分开处理**：`robots.txt` 本身当前返回 500（连基础爬虫访问都无法核实），更谈不上是否对 `GPTBot`/`ClaudeBot`/`PerplexityBot` 等 AI 爬虫做了任何区别于 Googlebot 的规则设计；`llms.txt`（部分站点已开始使用的、面向生成式引擎的补充清单）目前完全未被提及。
- **sitemap/robots 可靠性不在 P4 十项验收器的强制检查范围内**：两个试点页都是在这两个端点均 500 的情况下"通过"了 P4 验收，说明这是验收器本身的硬盲区，不是"尚未建设"的正常阶段性缺口。
- **转化路径（Handoff/CTA→sellersprite.ai）与 SEO/GEO 打分完全脱钩**：现有打分标准里没有任何类目衡量"页面是否在恰当位置、以恰当方式把决策级意图导向 CTA"，而这恰恰是用户本轮重申的业务北极星（免费流量→导流 sellersprite.ai）。目前 CTA 的正确性只被 `ARCHITECTURE.md` 的"关键不变量"约束（白名单域名、每页最多一个 CTA），从未被纳入过"这个页面有没有做好它的商业转化职责"这个打分维度。
