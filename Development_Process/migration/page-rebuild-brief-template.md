# 页面重构方案：<page>

> 用于首次重构一个 JSP 页面，或改变已确认页面的角色、信息架构、CMS 模型时。P1 证据完成后填写；**在人工明确确认前，不得创建 P2 schema、Sanity 内容或 P3 页面实现。**
>
> 旧站只能作为功能、字段、用户任务与事实证据。不要贴旧 DOM、旧截图或旧文案来替代新方案。

## 4. 内容、Sanity 与素材边界

| 内容项 | 类型（事实 / 新创作 / 运营维护） | 证据或素材来源 | Sanity / 代码归属 | 页面消费位置 | 留空 fallback |
|---|---|---|---|---|---|
| | | | | | |

规则：真实功能、价格、数据、客户、评价、比较结论和合规承诺必须有可复核来源；agent 可据事实改写，但不得编造。新文案应回答具体用户问题，避免泛泛形容词、重复卖点、关键词堆砌和模板化 AI 句式。新图片/插图先说明授权或来源策略；旧图片只有在权利清楚、事实仍准确且对新设计有价值时才可使用。

## 7. 实页验收计划

- [ ] 使用 Chrome/浏览器审查实际页面，而非只看组件代码；记录桌面与移动视口、路由和日期。
- [ ] 首屏能在无需滚动时表达页面价值、目标用户与主 CTA；CTA 数量/位置符合本页角色。
- [ ] 审查信息层级、可读性、留白、图片裁切、响应式、键盘可达性及动效是否服务任务。
- [ ] 检查文案具体、专业、可信且无明显模板化 AI 表达；不支持的主张已删除或标为 `UNRESOLVED`。
- [ ] 验证 Sanity 字段“发布 → 正确页面表面更新”，且 metadata 与可见文案不串扰。
- [ ] 按 P4 的 SEO/GEO、语义、运行时和测试要求保留证据。
