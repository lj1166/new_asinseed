# 元数据与图片素材设计约束（2026-07-26 新建，响应 `report-agent-system-gaps.md` 提案③）

## 定位与边界

本文档是与 `Development_Process/migration/seo-scoring-standard.md` 同级的标准文档，**不是新建 skill**。它规定 P2/P3 产出元数据（title/description/og:image/JSON-LD）时必须满足的硬性下限，堵住 `report-agent-system-gaps.md` §3.4 指出的验收盲区——P4 十项统一验收器此前只验收"字段来自 DTO 而非硬编码"（取证方式层面），不验收"DTO 里的值本身是否达标"（内容质量层面）。

触发证据（`/en`、`/zh-cn` 两份 SEO 打分报告已实测发现，非假设）：
- `/en` 标题 `"...Research Tool-AsinSeed"` 存在品牌名重复拼接。
- `/zh-cn` meta description 仅 11 字符（目标区间约 7%），`/en` 48 字符（约 32%）。
- 两个 locale `og:image` 均缺失。
- 两个 locale `jsonLdCount:0`。

## 1. 标题（title）规则

- **去重规则**：标题模板拼接时，品牌名（`AsinSeed`）只能出现一次。若页面标题本身已包含品牌名（例如首页 `"AsinSeed - ..."`），拼接层禁止再追加一次品牌名后缀；若页面标题不含品牌名，拼接层追加一次。产出前必须用简单字符串匹配自检：`title.split(brandName).length - 1 <= 1`。
- **长度预算**：目标区间约 50–60 字符（英文按字符数、中文同样按字符数，不做字节换算）。低于 35 字符判不达标（需补充核心关键词或价值主张短语，需真实文案，不得填充无意义词）；无硬性上限，但超过 70 字符建议复核是否会被 SERP 截断。
- **locale 一致性**：标题用字/措辞需与页面 `lang` 属性一致，不得中英混杂（专有名词/品牌名除外）。

## 2. Description 硬性下限

- **硬性下限：≥ 120 字符**（中英文均按此字符数下限，不做字节换算）。低于此下限，P4 验收器判 FAIL，**阻断该页通过验收**（见下方"与 P4 验收器的关系"）。
- 目标区间约 150–160 字符，120–150 区间视为"达标但有优化空间"，不阻断验收。
- 内容必须是该页面真实卖点/内容摘要，不得为凑字数堆砌无意义词或关键词填充（keyword stuffing）——这本身会被 GEO 打分标准 K1（直接可引用答案段落）间接检验，两者应互相印证而非矛盾。
- 若某页面类型确实没有 150 字符量级的真实内容可摘要（例如极简工具页），需在报告中显式记 N/A 并写明理由，不得为了凑字数编造内容。

## 3. `og:image` 规范

- **尺寸**：1200×630（Open Graph 官方推荐比例，约 1.91:1），格式建议 JPG/PNG，文件体积建议 <300KB。
- **素材来源决策流程**：
  1. P2 阶段：为每个页面类型（首页/结果页/内容页/表单页）确定 `og:image` 来源类型——"真实设计稿素材" / "页面真实截图" / "AI 生成占位图（需在文件名/alt 中标注`placeholder`）" 三选一，写入该页面的 P2 决策记录（如 `url-map.md`）。
  2. 未提供真实素材前，允许使用显式标注为占位的图片，但**不得**允许 `og:image` 完全缺失（当前两个 locale 的状态）——完全缺失在 GEO/社交分享场景下比"占位图"更差，因为分享卡片会显示为无预览图或平台默认图。
  3. 素材由谁提供：真实设计稿/截图需用户或设计资源提供；AI 生成占位图可由 agent 在获得用户批准后生成（生成图片属于内容策略决策，按 D-006 边界需先获批准，不属于"本地可逆小改动"）。
- 多个 locale 可共用同一素材（若品牌视觉一致）或分别设计，由用户决定。

## 4. 按页面类型的 JSON-LD 必需清单

与 `seo-scoring-standard.md` J1 子项判定标准一致，此处给出权威清单供 P2/P3 实现时对照：

| 页面类型 | 必需 JSON-LD `@type` | 说明 |
|---|---|---|
| 品牌入口页（如首页） | `Organization` | 至少声明 `name`/`url`；若有官方社交账号等可验证外部身份，另加 `sameAs`（见 seo-scoring-standard.md J2） |
| 含真实 FAQ 内容的页面 | `Organization` + `FAQPage` | **仅当 FAQ 为真实问答内容时才输出 `FAQPage`**（SDD §7.2 既有规则，非本文档新增）；FAQ 仍为占位内容期间禁止输出，避免把占位内容当真实数据编入结构化数据 |
| 含文章型内容的页面（blog/help/guide 等） | `Organization` + `Article` | `Article` 需要 `headline`/`datePublished`/`author` 字段，均来自真实数据，不得编造 |
| 结果页（查询结果，通常 noindex） | 无强制要求 | 该类页面按 P4 验收器第4项走 `noindex` 且不进 sitemap，结构化数据对其 GEO 价值有限，不作为硬性要求 |

任何页面输出的 JSON-LD 字段值必须来自真实数据源（DTO/Sanity），不得编造 `sameAs`、评分、评论数等无来源数据（呼应主提示词 §5.4 `schema-markup-builder` skill 描述的既有边界）。

## 5. 与 P4 十项验收器的关系

本文档规定的硬性下限（description ≥120字符、标题去重校验、og:image 非空、按页面类型JSON-LD齐全）已回填为 `prd-docs/prompts/00_migration_loop_master_prompt.txt` §2.3 统一验收器的补充硬性前置条件（见该文件新增的 §2.3.1 小节），与原有十项具备同等阻断扩批的约束力，不是可选建议。原十项条目本身未改动、编号不变。
